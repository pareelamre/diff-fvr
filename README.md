# Diff-FVR: Differentiable Fourier Volume Rendering

Research software for parallel-beam digitally reconstructed radiographs (DRRs)
and biplanar 3D–2D registration. It precomputes a padded 3D Fourier transform,
extracts a 2D frequency slice for each pose, and compares candidate projections
using a spectral similarity objective. Optional modules explore gradients,
articulated spine models, metal masking, and PyTorch acceleration.

**Research prototype. Clinical accuracy and suitability for surgical navigation
have not been established by the experiments in this repository.**

Author: Pareel Amre · TU Dresden · `pareel.amre@gmail.com`

## What the experiments establish

The `experiments/` directory contains 24 numbered simulation studies (plus the
9b magnification approximation). These explore rendering speed and fidelity,
registration convergence, noise, occlusion, truncation, articulation, motion,
and optional PyTorch acceleration.

Experiments 7, 12, and 13 each use one source CT volume and multiple randomized
poses. Their target images are generated by the same Fourier renderer used by
the optimizer, with optional synthetic noise. They are **same-renderer simulation
tests**, not registration against acquired fluoroscopy and not a multi-patient
clinical validation. Other stress tests simulate selected image effects; their
results do not demonstrate real-world robustness. mTRE uses eight synthetic
volume landmarks, not annotated anatomical landmarks.

Historical CSVs and figures in `outputs/paper_figures/` predate the physical-unit
correction. CT-derived error values were computed in voxels while labeled mm;
derived success rates and accuracy claims must be regenerated. The previous
README's numerical accuracy and speed claims are withdrawn pending verified
reruns with documented units, hardware, and an independent projection reference.
See [result limitations](outputs/paper_figures/README.md).

## Real Paired C-Arm & DiffDRR Benchmark (Experiments 25–26)

Experiments `25` and `26` evaluate Diff-FVR against **DiffDRR 0.6.1** (Siddon
cone-beam raycasting) on real paired pelvic CT + physical C-arm fluoroscopy
(`DeepFluoro`, `subject01`–`subject06`) with ground-truth $\mathrm{SE}(3)$ poses
and 3D anatomical fiducials (`128×128` interior crop, CPU):

- **Forward Speed & Perspective Fidelity (`exp25`, `subject01`, 10 views):**
  `10.9 ms` mean single-DRR latency (`~92 FPS`) vs. `1153.8 ms` (`~0.87 FPS`)
  for DiffDRR `0.6.1` (**`106x`** mean speedup), with `NCC(Diff-FVR, DiffDRR) = 0.9213–0.9863`
  (mean `0.9676`).
- **Bi-Planar Real C-Arm Registration (`exp25`, `subject01`, 4 pairs, init `9.69 mm`):**
  Diff-FVR (35 steps) runs in `1.9 s` (`7.04 mm` mean mTRE); a coarse-to-fine
  **Hybrid** (`30 Diff-FVR + 15 DiffDRR`) reaches `5.93 mm` in `62.1 s`, matching
  pure DiffDRR (`5.95 mm` in `103.3 s`) with `40%` lower runtime.
- **Multi-Subject Cohort (`exp26`, `subject01`–`subject06`, $N=6$):**
  **`78.7x`** mean forward speedup (`16.4 ms` vs. `1267.4 ms`), mean
  `NCC(Diff-FVR, DiffDRR) = 0.9550`, and `2.46 s` mean Diff-FVR registration
  vs. `167.11 s` for DiffDRR.

## Projection geometry and physical units

- `RobustDiffFVREngine` accepts a **cubic, isotropic** volume and spacing
  `(Z, Y, X)` in mm. Its poses use `(yaw, pitch, roll, tx, ty, tz)`, with
  rotations in degrees and translations/bounds in **mm**.
- The CLI preserves CT spacing while resampling to an isotropic cube that fits
  the longest physical dimension. NPY input contains HU values and defaults to
  one mm per voxel; use `--spacing-mm Z Y X` when this differs. DICOM spacing
  comes from its metadata.
- AP projects along Y, with X horizontal and Z vertical. Lateral projects along
  X, with Y horizontal and Z vertical. Targets must already match the rendered
  image shape, orientation, pixel spacing, and field of view. Arbitrary acquired
  X-rays are not automatically calibrated, rescaled, or registered in patient
  DICOM coordinates.
- This is a **parallel-beam** engine. SDD/SAD settings now raise an error rather
  than being silently ignored. `render_calibrated_drr` retains its legacy name
  for compatibility; it performs no cone-beam or perspective correction.
  Experiment 9b's isocenter scaling is an approximation, not a general calibration
  model. Full cone-beam geometry requires a separate implementation and validation.
- Low-level NumPy renderers, the original experimental registration engines, and
  gradients retain their existing **voxel-coordinate** conventions.
  They do not share the robust core's mm API. `compute_mtre_6dof` returns mm when
  passed measured `spacing`; use `translation_units='mm'` for robust-core poses,
  or the default `'voxels'` for low-level poses. Omitted spacing assumes 1 mm.
  The optional Torch backend is a separate experimental implementation; physical
  coordinate parity with the robust core has not been established.

Compatibility changes: the robust core interprets translations as mm even when
spacing differs from 1 mm; explicit SDD/SAD configuration is rejected.
`fvr.cli.load_volume` now returns `(attenuation_volume, spacing_zyx_mm)`.
Failed CLI optimization writes `success: false` and exits with status 1;
optimizer convergence alone does not establish registration accuracy.

## Install and try a simulation

```bash
pip install -e .

# Generate two synthetic targets on the same grid (parallel-beam model).
fvr-render --ct data/dicom --res 96 --view ap --tx 4 --ty 2 --tz 3 --out outputs/example_ap.png
fvr-render --ct data/dicom --res 96 --view lateral --tx 4 --ty 2 --tz 3 --out outputs/example_lat.png

# Recover the pose from those simulated targets.
fvr-register --ct data/dicom --res 96 --ap outputs/example_ap.png --lat outputs/example_lat.png --out outputs/example_pose.json

# Focused synthetic regressions and CT-based integration smoke test.
python tests/test_physical_units.py
python tests/test_core_engine.py
```

Optional Torch support: `pip install -e '.[torch]'`. Run its tests with
`python tests/test_torch_engine.py`; CUDA availability is environment dependent.

The [browser demonstration](https://pareelamre.github.io/diff-fvr/) is a scripted
illustration with synthetic images and an interpolated convergence animation.
It does not execute the Python registration engine or measure clinical accuracy.

## Repository

`src/fvr/` contains renderers, registration, metrics, DICOM loading and CLI code;
`tests/` contains synthetic regressions and integration scripts; `experiments/`
contains simulation studies; `docs/` contains the illustrative browser demo;
`outputs/paper_figures/` contains historical generated results.
